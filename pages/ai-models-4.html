4. Architecture Types

The underlying architecture determines capability ceiling, ecosystem compatibility, and which quantisation formats work.

Architecture Used In How It Works / Key Trait Examples
UNet SDXL, SD1.5, SD2.x Encoder-decoder with skip connections. Mature, massive community fine-tune ecosystem. Conv2d layers make GGUF quantisation impractical — use FP16/BF16 safetensors. sdxl_base_1.0.safetensors
DiT
(Diffusion Transformer)		 Flux.1/2, SD3, Qwen-Image, Z-Image Pure transformer architecture replacing UNet. Scales better with parameters, superior text following, more robust to quantisation. No skip connections. All Flux models, SD3
Flow Matching Flux family, SD3 Training/sampling method: learns direct flow paths from noise to image rather than iterative DDPM noise removal. Enables fewer inference steps. Flux.1, Flux.2, Flux.1 Kontext
S3-DiT
(Single-Stream DiT)		 Z-Image, Z-Image Turbo Text and image tokens processed as one unified sequence (not dual-stream like Flux). Enables smaller, faster models without separate cross-attention branches. Z-Image, Z-Image Turbo
LLM Text Encoder Flux.2, Z-Image, Qwen-Image Uses a large language model as text encoder instead of CLIP/T5. Flux.2: Mistral-3 24B. Z-Image: Qwen3-4B. Qwen-Image: Qwen-VL. Massive improvement in complex prompt understanding. Flux.2 Dev/Klein, Z-Image, Qwen-Image-2512
VAE
(Variational Autoencoder)		 All models Compresses pixel images to/from latent space. Separate swappable component. Quality affects colour accuracy, sharpness, and fine detail. Each model family has its own VAE. ae.safetensors (Flux.1), flux2-vae.safetensors
ControlNet SDXL, Flux (via adapters) Add-on model that conditions generation on depth maps, edge maps, pose skeletons, etc. Must match base model architecture. controlnet-depth-sdxl.safetensors
