Getting Started

How this documentation system works, why it exists, and how to add new pages without breaking anything.

This repository is a deliberately small, deliberately quiet alternative to the bloated documentation tools most people end up tolerating. There are no databases, no servers, no proprietary formats, no rendering quirks. Every page is a static HTML file. Every page can be opened directly from disk by double-clicking it, or served from any plain HTTP server, or pushed to GitHub Pages without configuration.

The trade-off is simple: you give up drag-and-drop block editors and the illusion of collaborative magic. In exchange you get formatting that does what you tell it to, files that will still open in twenty years, and a typography stack that respects the reader.

Repository structure

├── index.html              ← landing page with grid of all docs
├── docs.json               ← manifest: nav and metadata live here
├── assets/
│   ├── css/style.css       ← all styling
│   ├── js/site.js          ← builds nav, powers search
│   ├── fonts/              ← optional self-hosted fonts
│   └── img/                ← images referenced by pages
├── pages/                  ← every doc page goes here
│   ├── getting-started.html
│   └── style-guide.html
├── templates/
│   └── page.html           ← copy this to start a new doc
└── README.md

Adding a new page

  1. Copy templates/page.html into pages/ and rename it (kebab-case, e.g. q3-roadmap.html).
  2. Fill in the title, lede, meta line, and body.
  3. Add an entry to docs.json so it appears in the sidebar and the index grid.
  4. Commit. Push. Done.
Note
The sidebar and index grid are built at runtime from docs.json. You never edit nav links by hand. If a page exists but isn't listed in the manifest, it works as a deep link but won't appear in navigation — useful for drafts.

The manifest format

Each entry in docs.json looks like this: 

{
  "id": "q3-roadmap",
  "title": "Q3 Roadmap",
  "category": "Planning",
  "file": "pages/q3-roadmap.html",
  "excerpt": "What we're shipping between July and September.",
  "tags": ["planning", "roadmap"],
  "updated": "2026-05-05"
}

The category field controls how docs are grouped in the sidebar. Use consistent category names — "Engineering" and "engineering" will produce two separate groups.

Working with Claude

The intended workflow is to ask Claude to create or update pages. Useful prompts:

  • "Add a new doc called X about Y, category Z."
  • "Update the section on N in pages/foo.html with this new info: …"
  • "Refactor pages/bar.html into three smaller pages, update the manifest."
  • "Add a tag deprecated to every doc in the Legacy category."

Because everything is plain text, Claude can edit pages, restructure the manifest, and keep the index consistent without round-tripping through any opaque format.

Viewing and hosting

Locally

The fastest way to view the site locally is a one-liner from the repo root: 

python3 -m http.server 8000

Then open http://localhost:8000. You can also open index.html directly with file://, but some browsers block fetch() on local files, which means the sidebar nav will fail to load. Use the local server.

GitHub Pages

  1. Push the repo to GitHub.
  2. Settings → Pages → Source: main branch, root directory.
  3. Wait ~30 seconds. Visit https://<user>.github.io/<repo>/.
Caveat
If the repo is hosted at a subpath (e.g. /my-docs/), all internal links remain relative, so it works without modification. If you map a custom domain, also works without modification.
