0b. Component Internals

What kind of mathematical object each pipeline component actually is — the internal mechanics that make the compatibility rules intuitive.

The "what it does" view tells you how to use a component. This section explains what each component actually is — which makes the compatibility rules that follow make intuitive sense. A VAE trained on 4-channel latents and a VAE trained on 16-channel latents are not different settings of the same machine; they are different machines with incompatible outputs.

VAE — Variational Autoencoder

A neural network trained as a lossy compressor. Two halves: an Encoder (pixels → latent) and a Decoder (latent → pixels). "Variational" means it maps to a probability distribution in latent space, not a fixed point.

InternallyTrained separately from the diffusion model, then frozen. Compresses a 512×512 RGB image (786K values) into a small latent grid — e.g. 64×64×4 channels (16K values) for SDXL, or 128×128×16 for modern models. The diffusion model never sees pixels; it only manipulates these tiny latents. Because the VAE is lossy, reconstruction is not pixel-perfect — which is fine because the diffusion model fills in details from training anyway.
Key factsSDXL: 4-channel, 8× spatial compression  ·  Flux / Qwen / Z-Image: 16-channel, 8× spatial compression — richer encoding, better fine detail  ·  Files: ae.safetensors (Flux.1), flux2-vae.safetensors (Flux.2)

Text Encoder — CLIP / T5 / LLM

A neural network trained to map text into a high-dimensional vector space that the diffusion model can be conditioned on. The diffusion model learns to associate these vectors with visual concepts during training.

InternallyCLIP was trained by matching image-text pairs — it understands visual-semantic similarity but is limited in contextual reasoning. T5 is a sequence-to-sequence language model — it understands grammar, relationships, and negation much better. The encoder output is a tensor [batch, seq_len, hidden_dim] — each token becomes a vector. The diffusion model uses cross-attention at every layer to query this conditioning throughout the denoising process.
Key factsCLIP-L: 77-token limit, semantic matching  ·  CLIP-G (SDXL): larger CLIP, better style  ·  T5-XXL (Flux.1): 512-token limit, language understanding  ·  Mistral-3 24B (Flux.2): 32K-token limit, full LLM reasoning  ·  Qwen3-4B (Z-Image)  ·  Qwen-VL (Qwen-Image)

Scheduler — Noise Schedule

A mathematical function that defines how much noise exists at each step of the diffusion process, and how to compute the update from one noisy state to the next. Not a neural network — it's an algorithm.

InternallyDuring training, a random noise level (timestep t) is sampled, noise is added to the image latent, and the model learns to predict what noise was added. During inference, you start at t=T (pure noise) and run backwards. DDPM uses a fixed Markov chain. DPM++ uses ODE solvers to take larger, more accurate steps. Karras uses non-linear noise spacing that concentrates steps where they matter most. Flow Matching (Flux) uses straight-line trajectories in probability space — which is why DDPM schedulers don't work on Flux.
Key factsDDPM / DDIM: original formulation, 50–1000 steps  ·  DPM++ 2M Karras: best quality/speed for SDXL, ~20 steps  ·  Euler / Euler a: fast SDXL iteration  ·  Simple / SGM Uniform: Flow Matching (Flux)  ·  DPM++ 3S: fast option for Qwen-Image (~10 steps)

KSampler — Denoising Loop

Not a model — it's the inference loop that calls the diffusion model N times. At each step it asks: "given this noisy latent and this prompt, what noise is here?" then uses the scheduler to take one denoising step.

InternallyEssentially: for t in reversed(timesteps): noise_pred = diffusion_model(latent_t, t, conditioning); latent_{t-1} = scheduler.step(noise_pred, latent_t, t). Also applies Classifier-Free Guidance (CFG): runs the model twice per step (conditioned + unconditional) and extrapolates toward the prompt. CFG=7 means "move 7 steps in the direction of the prompt". Flux bakes guidance in via distillation — CFG=1, one pass per step, twice as fast.
Key factsSteps: 20–50 standard, 4–8 for distilled  ·  CFG Scale: 7–9 (SDXL), 1.0 (Flux), 3.5 (Flux dev)  ·  Denoise: 1.0 = txt2img, <1.0 = img2img  ·  Seed: controls initial noise pattern

LoRA — Low-Rank Adaptation

A fine-tuning technique that adds small trainable matrices alongside the frozen weights of a pre-trained model. At inference, the LoRA weights are merged with the base model at load time. Not a separate network — it modifies the existing one.

InternallyInstead of fine-tuning all N billion parameters, LoRA decomposes the weight update into two small matrices: ΔW = A × B, where A and B have rank r (typically 4–64). A 12B parameter model can be personalised with only 10–200 MB of adapter weights. Multiple LoRAs can be stacked. LoRAs trained on Flux.1 dev will NOT work on SDXL — they encode weight offsets for a specific architecture.
Key factsFile size: 10 MB – 300 MB  ·  Rank: 4 (minimal), 16–64 (typical), 128+ (high capacity)  ·  Scale: 0.5–1.0 safe, >1.5 risks artefacts  ·  Must match base model architecture exactly

Conditioning — Embeddings

The output of the text encoder — the numerical representation of your prompt that guides the denoising process. A tensor of floating-point vectors, one per token, passed into the diffusion model via cross-attention at every layer.

InternallyTensor shape: [1, seq_len, hidden_dim] — e.g. [1, 77, 768] for CLIP-L or [1, 512, 4096] for T5-XXL. Every transformer layer in the diffusion model has cross-attention heads that query this conditioning, asking "how relevant is each token to this patch of the image right now?" This is why longer structured prompts work better with T5/LLM encoders.
Key factsPositive conditioning: what you want  ·  Negative conditioning: what you don't want (not used in Flux — no unconditional pass)  ·  Empty conditioning: unconditional baseline for CFG  ·  Strength controlled by CFG scale
